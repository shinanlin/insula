# 05 单电极反应时预测、描述性编码与 Figure 5

入口：[Figure 5](../../vizpub/fig5.ipynb)。数据构造：[insula_rt_data.py](../../src/reaction_time/insula_rt_data.py)；模型/校正：[insula_ridge.py](../../src/reaction_time/insula_ridge.py)；运行：[run_insula_rt_ridge.py](../../src/reaction_time/run_insula_rt_ridge.py)；汇总：[summarize_insula_rt_ridge.py](../../src/reaction_time/summarize_insula_rt_ridge.py)、[summarize_insula_rt_encoding.py](../../src/reaction_time/summarize_insula_rt_encoding.py)。

## 1. 样本和分析单位

任务为 LD、PS、PN，条件 Repeat，phase 为 Delay、Go、Response。每位被试、每个任务分别建模；在该被试每个 strict AIC/PIC 双极电极上，逐时间窗预测该 trial 的反应时。

输入为完整 `epoch(band)(zscore)`，**没有先限制为显著响应电极或 NMF 电极**。loader 要求 gross ROI 恰为 AIC/PIC；没有额外重复执行 NMF 的 mix/排除名单流程。跨 recording 合并时，按 phase 取共同可用通道。NMF 标签只在结果汇总时附上，未入 NMF 的岛叶电极可以有 RT 结果并归为 unassigned。

此次核对到 300 个 H5：LD 38、PS 35、PN 27 个 subject×task 单元，每单元 3 个 phase；总计 100 个 subject×task 单元、**63 个独立被试**。不要把 100 当成独立被试数，也不要把 worker 候选名单数当成成功生成模型数。每个文件的 trial/channel/item/fold 数见 [rt_results.csv](evidence/rt_results.csv)。

## 2. RT 的事件配对与筛选

目标定义 `RT_seconds = response_onset − go_onset`。事件 sample 来自原始数据，默认原始采样率 2048 Hz；不能除以降采样后的 128 Hz。多 recording 必须各自解释 sample/onset，不能直接跨 recording 拼绝对 sample。

- Delay 对齐 trial：找相同 item 的后续 Go，以及该 Go 后、下一 Go 前的第一个相应 Response。
- Go 对齐 trial：使用匹配 Go 与后续 Response。
- Response 对齐 trial：对应此前 Go 及该 Response。

保留有限 RT 且 `RT≥0.05 s`；当前没有统一上限、winsorization 或按每位被试删若干 SD 的步骤。目标为 `y=ln(RT_seconds)`，自然对数。

LD/PS 通过事件中的类别与词字段构建 item ID；PN 用文件 stem 对应的概念 ID，image/sound/text 可以共享同一个概念 group。PN 的 4 个概念是分组 CV 的单位，不是把每种 modality 当成独立词。

**实现与历史结果的边界**：当前 RT loader 的 `.str.contains("CORRECT")` 存在同时匹配 `INCORRECT` 的潜在问题。本次检查全部 300 个已保存文件的 target event 标签，未发现 INCORRECT，因此不能称这些现有结果已被错误 trial 污染。迁移实现应使用 slash token 精确匹配，并保存纳入事件审计表。这里只记录问题，没有修改原分析代码。

保存 trial metadata 包括 target/go/response 名称、sample、onset、recording、source row/file、trial UID、item ID、原始和 log RT、fold ID。

## 3. 滑窗：请求时间和实际时间

完整 epoch 为 320 点、128 Hz，时间 `[-1,1.5)`。每 trial、每电极、每窗的特征是该窗内所有 HGA 采样点；不先把整个窗平均为一个数，也没有 5-bin LDA 那一步。

| 参数 | 请求值 | 在 128 Hz 的实际实现 |
|---|---:|---|
| window | 0.2 s | `round(0.2×128)=26` 点 |
| step | 0.02 s | `round(0.02×128)=3` 点 |
| 实际步长 | — | 3/128 = **0.0234375 s** |
| 26 点对应采样长度 | — | 26/128=0.203125 s |
| 首末采样的时间差 | — | 25/128=0.1953125 s |
| 每阶段窗口数 | — | 99 |
| 第一窗 | — | start −1、end −0.8046875、center −0.90234375 s |
| 最后一窗 | — | start 1.296875、end 1.4921875、center 1.39453125 s |

存储/绘图时间使用实际 window center；与 Figure 4 LDA 的 window end 横轴不同。不能在论文里只写“20 ms sampling of prediction”而隐去实际 23.4375 ms 的计算网格。

## 4. 外层预测与内层选 alpha

每个电极、每个窗口使用同一组 item folds，保持横向比较可解释。

| 参数 | 设置 |
|---|---|
| 外层 CV | shuffled GroupKFold by item；`min(10,n_unique_items)` folds |
| 外层 seed | 42 |
| 内层 CV | 对外层训练集的 item 分组；`min(5,n_training_items)` folds |
| 内层 seed | `42+outer_fold_index+1` |
| 内层传递 | 以 `PredefinedSplit` 交给 Himalaya RidgeCV |
| 缺失值 | `SimpleImputer(strategy="median", keep_empty_features=True)` |
| 缩放 | `StandardScaler` |
| 回归 | Himalaya `RidgeCV`，`fit_intercept=True`，default solver 对应 SVD 路径 |
| alpha grid | `logspace(-3,3,10)` |
| 内层选择指标 | negative L2 loss；不是 Pearson r |

alpha 精确网格为：`0.001, 0.0046415888336, 0.0215443469, 0.1, 0.464158883361, 2.15443469003, 10, 46.4158883361, 215.443469003, 1000`。

PN 只有 4 个概念，所以外层实际 4 folds，每次留出一个概念；内层实际 3 folds。LD/PS 的可用 item 数通常足以使用请求的 10/5。不能把所有任务统一写成外层 10 折。

pipeline 的 imputer/scaler 在外层训练集上拟合一次，之后 RidgeCV 在其输出中做内层 alpha 选择。因此外层测试数据没有进入 imputer/scaler，但这些变换**没有在每个内层训练 fold 再独立拟合**。应描述为外层隔离测试、内层选 alpha，不能声称全部预处理都严格嵌套。新项目如需严格嵌套，可改成每个内层 split 独立拟合完整 pipeline。

Himalaya 可一次把观察 y 和置换 y 当成多个 targets 拟合，`local_alpha=True` 对各 target 独立选 alpha，`conservative=False`。该并行实现不表示观察 y 与置换 y 共享最优 alpha。参数语义参考 [Himalaya RidgeCV 官方文档](https://gallantlab.org/himalaya/_generated/himalaya.ridge.RidgeCV.html)，以本次检查的 0.4.8 实现为准。

## 5. OOF 评分及置换 null

拼接全部外层留出 trial 的预测，计算：

- Pearson `r(y_true,y_oof)`：主预测分数。
- `R²=1−Σ(y−ŷ)²/Σ(y−mean(y))²`：允许负值，不裁为零。
- `MAE=mean(|y−ŷ|)`：单位为 log-seconds，不是毫秒。

1000 次置换在**每个外层训练 fold 内**无约束打乱 trial 的 RT 值；测试 y 保持真实，item CV 分组保持原样。它不是 item-level RT shuffle，也没有按 recording 或条件分块限制交换。每个置换 target 重新进行内层 alpha 选择。

置换 seed 表由 root seed=42 生成，在同一 subject×task 的 channels/windows/phases 间复用，支持后面的共同 max-null。只报告 Pearson 的参数检验 p，或只重排最终预测而不重拟合，都不等价于本方法。

## 6. 时间簇与校正范围

函数 `joint_cluster_correction` 接收一个 subject×task 本次运行的 phase 集合，输入观察 `r[channel,time]` 及 null `[channel,time,1000]`。

1. 逐点上尾 p=`(1+#finite_null>=r)/(1+n_finite_null)`；观察 supra-threshold 取 p≤0.05。
2. 各 cell 用 null 第 95 百分位作阈值；每次置换以严格大于阈值的时点组成连续时间簇。
3. 每次置换取**所有参与 phase、所有电极**中的最大簇长度。邻接只沿每个电极自己的时间轴，不在相邻电极之间连簇。
4. 观察簇长度为 L，`cluster_p=(1+#null_max_length>=L)/1001`。
5. `cluster_p≤0.05` 且观察 r>0 的时点标为预测显著。

family 是 subject×task×本次联合 phases，而不是全数据集。现有主启动文件先联合跑 Delay+Go，Response 在独立脚本里以单独 phase 补跑；所以是 **Delay/Go 一组，Response 另一组**，不能说三阶段联合校正。H5 未完整保存每次联合 phase family，判断还依赖对应启动脚本，这是 provenance 限制。

外层/内层都至少需要 2 个可用 item group。某电极窗如发生 ValueError、浮点错误或线性代数错误，当前拟合会将该窗分数置 NaN；没有将失败模型当成 r=0。`max_windows` 是调试限制，完整已保存结果均有 99 个窗口。

这里控制的正向 r 表示“预测值与真实 RT 一致”。它不意味着“HGA 越大 RT 越长”；单电极窗口有多个 Ridge 系数，其振幅方向须另行分析。

## 7. Figure 5 的显著预测曲线、raster 和空间图

Notebook 读取 `results/rt/summaries/coverage.csv`、`electrodes.csv`、`significant_clusters.csv`。缓存为 300 coverage 行、2178 electrode×phase 结果行、319 个显著时间簇。

上述旧预测汇总中有 42 行 electrode 记录和 11 行显著簇记录的功能标签与当前 assignment 不同，涉及 NMF 章节列出的同 6 个电极。较新的 `hga_rt_encoding_electrodes.csv` 标签与当前表一致。因此旧 raster 的群计数与新振幅 panel 的分组不能默认视为同一标签冻结版本。

hit 定义：显著簇满足 Delay 的 `end_time>0`，或 Go/Response 的 `start_time<0`。这只要求与目标区间**有重叠**，不是整个簇严格在 Go/Response 前。按 task×subject×channel 去重后缓存 103 个 hit；再限制到有 NMF 标签者，raster 缓存 68 行（motor 42、sustain 20、sensory 6）。同一电极在两个任务中出现可占两行，不能读成 68 个被试或 68 个跨任务唯一电极。

曲线保留这些 hit 电极在各阶段中 FWER 显著且正向的 r，再按群平均并画 SEM。由于先按显著性选择时点/电极，均值是**所选显著结果的描述**，不是所有电极的无偏预测性能估计。图上平滑为 sigma=2 的 Gaussian，实际约 46.875 ms，只在连续有限片段内平滑，不跨 NaN 缝隙。raster 的 0.02 s 显示网格是插值网格，不是重新计算模型的步长。

行排序使用功能群及起始时间等显示规则；不同事件锁定窗的时间不能当成同一绝对时间直接解释。空间 panel 将 hit 对应通道去重并合并坐标，绘到模板 pial 表面；surface 投影是显示，不提供额外统计检验。

## 8. HGA–RT “encoding” panel 实际做了什么

这一部分另读 `hga_rt_encoding_electrodes/subjects.csv`、`hga_rt_trials.csv`、`hga_rt_go_traces.csv` 等。不是又拟合了一套多电极 RT decoder，也不是用 NMF component 预测 RT。

### 8.1 选电极与窗口

只考虑 Go：在 FWER 显著、OOF r>0、`window_start<0` 的窗口里，每个 task×subject×electrode 选预测 r 最大的一个。这个窗可能跨过 Go=0，所以准确措辞是“起点在 Go 前的窗口”，不能写成严格截止于 Go 前。使用当前 NMF assignment 分组。

将选中窗口的原始 trial HGA 用 `np.mean` 沿时间求均值；有 NaN 的均值在相关分析中被排除。每个电极求 mean HGA 与 log RT 的 Pearson r、OLS slope。subject×task×cluster 单元至少需 16 个有效 trials，电极相关在单元内取中位数写入 subjects 表。

同一数据既用于选择最能预测的电极/窗，又用于展示振幅关联；该部分是选择后的描述性分析，不是独立确认的负相关证据。

### 8.2 快/慢 trial 波形

先在每个 task×subject×cluster 内，对被选电极的完整时间序列求 trial-level 平均，去除 HGA 或 target 不完整的 trial。以该单元 log RT 中位数分组：fast<median，slow≥median。跨 task×subject 曲线再平均并画 seaborn 默认 95% bootstrap CI；不是在全项目用一个共同毫秒阈值分 fast/slow。

### 8.3 散点与群体方向检验

散点先对每个选中电极的窗均值在其有效 trials 内做 z-score（ddof=0），再跨电极 `nanmean`，与 log RT 配对。这个相关不一定等于 subjects 表中“各电极 r 的中位数”，两者聚合顺序不同。

功能群方向检验先在 subject 内对各任务的 r 取中位数，之后对被试做单侧 Wilcoxon，alternative="less"，对照 0，至少 2 个被试；三个群未额外多重比较校正。选择后的效应仍应按描述性结果解释。

Notebook 中叫 `typical` 的例子实际上通过 `mean_hga_log_rt_r.idxmin()` 选择，即该群**相关最负的 task×subject 例子**，不是最接近中位数的典型被试。迁移时应准确命名，或在独立规则下另选代表例子。

仓库还有 LMM 方向分析/其他 summary 表，但 Figure 5 未使用这些表作为上述 panel 的来源，不能把那些模型自动写入该图主方法。

## 9. 复用与验收

验证事件配对时逐条检查 Go/Response 所属 item、recording、原始采样率及 RT 正值；保留剔除计数和原因。验证 CV 时要求 train/test item 无交集，PN 实际 fold 数正确。验证结果时要求每个 trial 恰有一份 OOF 预测，window indices 与保存的 center 一致，null schedule 在联合 family 内一致。

新项目应在分析前固定 joint phase family、单侧方向、cluster statistic 和 item/trial 交换假设。若做“严格动作前预测”，应筛 `window_end≤0` 而非只筛 start<0；若需要确认振幅–RT 关联，应另划验证数据或嵌套选择窗口。这些是新的分析设计，不能在不重跑的情况下宣称现有 Figure 5 已满足。
